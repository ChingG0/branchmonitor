# V10 手動 V1

使用者於 2026-10-22 要求複製 V1，之後與 V3、V6 一起在對話中手動更新。原 V1 繼續自動計算。V10 先複製截至 2026-10-21 的 V1 全部策略結果，包括 100 萬元初始本金、歷史曲線、候選、持股、成本與停損；沒有重新空手起跑。

V10 是同規則的按需保存複本，不是新投資邏輯。沒有因改成手動更新就調整分數、機率或承諾更佳績效。每次更新仍以當時本機 V1 規則重算截至指定日，再另外保存；來源事後修正可能使新快照的重播結果不同，舊快照原檔不變。V1 原始歷史不是人工逐日決策績效。

## 更新授權與順序

後續使用者要求「更新 V3、V6」或「更新 V3、V6、V10」時，一併手動更新 V10。2026-10-29 起也包含 V11，依 `docs/V11_MANUAL.md` 另存其獨立帳戶；不要把 V10 持股複製給 V11。若明確指定只更新其中一項，依指定範圍處理。普通前台資料更新、全部更新、排程、讀取 API、切換日期及重新整理頁面，都不得呼叫 V10 publish。

1. 先完成所選日期的行情、RS 與分點資料核對，並按既有文件更新 V3、V6。
2. 讀取 `python -m backend.v10 report`，取得 expected_revision；未建立時為 0。
3. 準備 JSON：`{"expected_revision":0,"as_of":"2026-10-21","analysis":"說明此次資料與市場研究，標明來源缺漏；新聞研究不改寫 V1 策略分數與交易規則。","sources":[{"title":"來源標題","url":"https://example.com"}]}`。
4. 執行 `.venv/bin/python -m backend.v10 publish --decision /absolute/path/decision.json`。只有此命令保存新快照，使用實際時間；不能把收盤後或隔日才知道的人工論點說成早已用於歷史成交。
5. 核對 V10 日期、版號、持股、績效及 `data/v10_manual/` 新檔；舊檔不可覆寫。V3/V6/V10 各自保存，任一失敗須個別報告，不宣稱三者都成功。

V10 使用 `v1.report(cutoff=as_of)` 的同一套計算，保存時深拷貝，以免更動 V1 快取。`GET /api/v10` 及每日跟單只讀已保存的資料，不讀行情重算。未新增任何前台更新端點。若之後要求人工變更選股或預算，需明確另建規則與獨立交易帳本，不能將本複本直接包裝為已完成的人工帳戶。
