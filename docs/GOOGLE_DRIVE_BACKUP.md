# 手動更新後的 Google Drive 增量備份（包5）

只有使用者在對話要求更新 V3／V6／V10／V11 後執行。備份不呼叫任何策略、預報、成交核對或行情更新。前台、GET、排程及 report 不排隊。成功的正式 CLI 發布只寫待備份通知，失敗不撤銷已保存策略；直接呼叫 publish 函數的人工批次，須在最後自行執行下列備份步驟。

## 每次對話更新完成後

1. 核對各策略保存成功，再執行 `.venv/bin/python -B scripts/drive_backup.py prepare`。一次批次四策略只建立一份增量。它會比較首次390,340檔基底與已確認增量，SHA256逐檔檢查；變動SQLite用backup API和integrity_check，其他檔案切8MiB內容區塊後壓縮。不重新發布策略。
2. 讀回輸出的版本目錄 `UPLOAD.json`，用對話內已連接的Google Drive工具完成上傳。一般Python／前台沒有這個連線權限，不假裝背景自動同步。首次基底在私人資料夾 `1pdLe0BKu_eFyV4PY7mm8uD4RxW_eR9tJ`；增量各建獨立資料夾，置於主備份資料夾 `12cXagS0uIHl69I5dSYaWryNzfC9pHLdw`。
3. 上傳前核對目的資料夾的父層、owner-only權限及可用Google One配額。20GB是本專案預算，不是帳號剩餘容量。已確認的雲端區塊不重傳；本機區塊均再驗雜湊。每檔小於100MiB工具上限。中斷時先比對同名檔的實際內容，不能同名就當成功；續用同一資料夾，避免重複建立。
4. 每檔實際從Drive讀回，以SHA256與本機UPLOAD清單核對。保存 `RECEIPT.json`，含 `folderId`、`ownerOnly:true`、`verifiedAt`，`files`陣列每筆含`name/fileId/bytes/sha256/readBackSha256`。這是操作員依工具結果填寫的校驗證據，腳本本身沒有Drive授權，不能替工具證明雲端狀態。
5. 執行 `.venv/bin/python -B scripts/drive_backup.py confirm --version <版本絕對路徑> --receipt <收據絕對路徑>`。校驗成功才最後寫 `CONFIRMED.json`；將收據及確認檔上傳到該版本資料夾，讀回核對。未確認前一直是待備份；`status`可查看待處理數量。
6. 更新結論須分開說明策略是否成功、雲端是否完成；備份失敗時保留待處理，不把資料來源缺失或硬碟不足說成成功。

## 版本、容量與安全

`60-更新後備份/`在獨立準備資料夾下，含不可變通知、版本清單、內容區塊。增量MANIFEST記錄父版、變更、刪除、原保存時間、實際擷取時間與程式commit。刪除只記錄還原狀態，不刪來源檔或雲端舊檔。只有完整確認的父版才能被後續版本引用；未完成版本先續傳，不能越過。

不需要改動的歷史和研究全部沿用首次基底，第二次無變更只傳一個清單。變動的大SQLite仍需短暫完整一致性快照空間；不足就明確失敗保留待處理，不能拿正在寫入的db硬拷貝。每次掃描核對主檔及WAL狀態，變動中拒絕封裝。不同DB只有各自一致，不宣稱跨DB單一交易。

20GB預算含首次2.579GB、已確認版本及下一版預估；超過預算停止，不自動購買或清理。完整基底與其增量依賴鏈全部保留。包6還原演練前，雲端／本機的自動刪除一律關閉。之後若只留最近三份，必須先另做可獨立還原的新完整基底，不能直接刪父版。Google One與Gmail／相簿共用，仍須另查實際剩餘配額。

## 還原格式

先依包4工具還原首次基底，再按父鏈順序套用增量：每個changed檔按chunks順序解gzip、串接、驗證全檔sha256和bytes；依原相對路徑寫到新的還原目錄，最後處理deleted。區塊可能位於更早已確認版，依其收據定位。禁止直接覆蓋正式資料。完整雲端下載還原演練屬包6，本包只驗證增量及小型測試資料。
