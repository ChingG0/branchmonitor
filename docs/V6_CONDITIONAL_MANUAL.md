## 對話更新流程

沒有使用者要求更新V6時，只能讀`python -B -m backend.v6_conditional status`。頁面、HTTP、排程不呼叫任何更新／評分／啟用命令。

更新V6時，先取得並保存本次來源原檔，按照下述格式整理來源包。將**絕對路徑**放進V6研究草稿的`conditional_bundle`欄位，再執行原有`backend.v6_weather`發布；其CLI會在原V6報告保存後，將本次來源交給觀察器。不要再重複執行同一份觀察更新。

若只要求更新條件預報，可獨立使用：

```bash
.venv/bin/python -B -m backend.v6_conditional update --bundle /absolute/path/bundle.json
```

未能整理完整來源時，仍應如實記錄缺項。`update`不帶bundle會保存缺來源狀態，不產生百分比。原V6流程缺少`conditional_bundle`時亦同。此包不自動抓新聞或把AI文字判斷轉成機率。

初次`enroll`只保存實際起跑時間，不生成任何預測；不得重設。此命令已在包8完成時執行，不要重跑。

## 時間與樣本資格

- 所有模型輸入須在當天08:30以前已可取得；來源原檔與實際取得／保存時間另存，不以重建發布時間冒充原始證據。
- 合格發布只接受**當日08:30～08:44:59**的實際保存時間。CLI沒有`--now`、`--date`或直接輸入機率選項。提前、開盤後或盤後更新可以核對已成熟結果、保存來源與缺項，但不倒填當日合格預報，也不自行建立隔日08:30預報。
- 同版本／同決策日／同期限只計第一份合格預報；重複更新保留原機率。
- T+1是決策日當天收盤，T+2、T+3是之後兩個實際交易日收盤，均相對決策日前一交易日收盤。
- 夜盤使用決策日歸屬的盤後資料，和上一現貨交易日的同合約一般盤收盤比較。連假期間海外窗口累積；美國夏／冬令時間沿用包3規則。
- 三個期限在相同來源資格下平行保存M0／M1／M2。包4參數與尺度不重訓；M1是歷史合格候選，M2只作比較，R2不接入。
- 到期日13:30以前不評答案。新取得的官方交易日曆若順延到期日，另存異動事件，保留原定日期及日曆雜湊，不覆寫原預報。
- 每次對話更新才核對新成熟結果、重新檢查接入資格與退回條件。讀取畫面不補算。

## 來源包契約

`bundle.json`包含`decision_date`（本次查核的決策日）及`sources`。後者必須具備九項：`cash`、`tx`、`tsm`、`sox`、`spx`、`vix`、`fx`、`stock2330`、`calendar`。

每項包含：

```json
{
  "file": "normalized.csv",
  "sha256": "正規化檔案完整SHA256",
  "raw_file": "retrieved-original-file",
  "raw_sha256": "實際取得原檔完整SHA256",
  "available_at": "帶時區且有來源支持的可取得時間",
  "source_url": "https://原始來源網址"
}
```

檔案路徑相對bundle所在目錄，亦可用絕對路徑。觀察器將兩份檔案的完整位元組、來源網址、雜湊及實際保存時間一起封存。雜湊只能證明保存後內容未變，不能證明人工整理的數據一定正確；整理時仍須對照原檔，不得虛構可取得時間。無可靠時間證據應留缺、不得宣稱合格。

正規化欄位沿用包1～3：

| 來源 | 檔案與必要欄位 |
|---|---|
| cash | CSV：date,open,high,low,close；至少涵蓋目前前61個完整現貨交易日，核對到期結果時附新成熟日 |
| tx | CSV：date,contract,session,open,high,low,close,volume；session為一般／盤後，date採期交所交易歸屬日 |
| tsm／sox／spx | CSV：date,close；包含前一現貨收盤當時已知的美股基準日，到最新可用美股日之間每個交易日 |
| vix | CSV：date,CLOSE；精確配對最新美股參考日 |
| fx | CSV：date,ntd_per_usd,publication_bound；包含現貨錨點及決策截點當時已公布資料 |
| stock2330 | CSV：date；確認台積電錨點交易日資料存在，ADR直接用其本身跨日報酬，不以ADR價格當台股價格 |
| calendar | JSON：sessions為完整排序且不重複的交易日期，涵蓋前61日及本次三個到期日；保留實際官方公告原檔，臨時休市需更新 |

不可用合成連續期貨替代同合約，或把盤中行情當夜盤完成收盤。完整性不足即停止新條件機率。`available_at`是資料可取得時間；實際取得時間由觀察器的capture事件另存。

## 啟用、退回與恢復

每個期限獨立檢查：至少經過60個實際交易日、至少60筆成熟共同合格預報、上漲／下跌各20筆；M1相對M0的Brier改善至少1%，log loss不劣。這是最低操作門檻，不等於統計證明。

達標僅顯示「符合門檻」，不自動啟用。使用者授權後才可執行：

```bash
.venv/bin/python -B -m backend.v6_conditional activate --horizon 1
```

只能啟用歷史合格M1，不能藉此啟用M2或R2。當前來源不完整也不能啟用。正式啟用後的M1條件預報在本頁的條件預報卡片呈現，原歷史基準、已存紀錄與交易策略仍分開保存。

每次對話更新在新答案成熟後檢查最近60筆共同預報；M1 Brier劣於同日期M0時暫停該期限，停用新條件機率（M0仍保留為評分基準，主畫面不以其歷史比例代替預測）。來源或完整性失敗則停止新的條件機率，保留上次帶日期紀錄。停用後需至少60筆**停用之後才發布**的新成熟合格預報、正反例各20筆及相同改善條件，再經對話授權才能恢復；隔天轉好不會自動跳回。

## 保存與驗收

- 程式、包3特徵構造、包4參數及包1～7父封存雜湊在`config/v6_conditional/release.json`核對。

## 每日漲跌機率走勢（2026-11-06）

原V6對話發布完成觀察更新後，自動匯出`daily-probability-history.json`。這是已存M1預報的唯讀顯示衍生物，不改動已封存模型、發布時段、接入資格或交易策略。若獨立執行條件預報更新，完成後再執行一次`python -B -m backend.v6_probability_history export`；不要為了重新畫圖重跑觀察更新。`report`只讀，`export`只寫顯示檔，不取行情、不核對答案、不建立前瞻樣本。

預設顯示「實際保存」，可切T+1／T+2／T+3、20／60／全部日期。每點保留實際保存時間、資訊截點、原定及目前到期日、較前筆有效預報變化。每個點是不同起點的新預報，不能視為同一到期日的機率修訂。缺項日斷線，沒有更新的日期不補造或沿用前值；新市場研究和新有效機率各自標時間，盤後保存市場資料不代表已生成新機率。到期結果另列，不把0／100結果接成預測。

上方固定顯示以最新已保存加權收盤日為T的未來三個交易日，日期取自已封存來源包的交易日曆；休市與週末不佔期限。未取得已公告日曆時顯示待確認，不用工作日猜測。僅當同錨點、同到期日已有合格M1保存紀錄才顯示機率，否則先列日期、機率待更新；日期預列不新增觀察筆數，也不推算或套用歷史機率。此區在實際／歷史模式都顯示；歷史圖橫軸明示為當時盤前預報日，不是未來到期日。

「歷史研究參考」須明確選擇，讀取原封存M1研究資料，不混入實際走勢，也不增加0／60觀察進度。重新整理和GET只讀取靜態檔。


## 夜盤收盤情境（2026-11-06）

使用者於11/6盤後要求更新未來三日機率；新增獨立`backend.v6_night_scenario publish`，只依對話執行。它不是新的已驗證盤後預報，也不解除原08:30資格限制。

此試算假設目前夜盤價格及高低區間維持到已知收盤時間，將原M1的四個夜盤／波動特徵套入固定參數與固定校準器；顯示的是該假設下原08:30模型的情境值。夜盤盤中可能再改價、擴大區間，原模型也尚未驗證這個時段的校準，所以不得套用原歷史命中率或稱為即時預報。週末／連假跨日時間仍依實際已封存交易日曆計算。未完成夜盤不假裝已完成，不加入缺值海外特徵，也不主觀用新聞加減機率。

僅在目前進行中的同一夜盤、報價15分鐘內、同合約日盤有基準、61筆已完成官方現貨收盤與後三日曆完整時才保存；否則停止。每筆在`data/v6_night_scenarios`獨立追加，保留行情原檔、時間、模型參數SHA與情境假設。`v6_probability_history export`唯讀投影同錨點／同到期日的情境，列在上方三日卡片；正式機率有合格保存時優先顯示，情境不混入正式走勢、0/60、命中率或交易策略。GET不抓行情、不發布。


## 情境走勢、後三日預列與滾動紀錄

「對話情境（最新）」為新增預設檢視，從獨立已保存情境讀取，不把08:30缺項改成合格預報。圖上同時列T收盤基準及三個到期日；三個情境點代表同一保存時點的不同期限，不是未來三次已發佈更新。每組固定收盤基準、到期日與模型版本，保留最初和所有追加版本，可切換保存時間。收盤對照預先列出三列，未到期／未手動核對為空，不能用今天收盤當未來結果。

同錨點、相同三個到期日、相同參數版本的再次夜盤情境發佈才是本組修訂，顯示對前次差值。跨日換錨點、或換模型／到期日則另建一組，不把新基準下的機率冒充對舊基準的修訂。原M1只有對起點收盤的二分類機率，沒有驗證可將新錨點機率換算成舊錨點的跨日修訂；此處不臆造那種換算。

情境方向核對與Brier只使用本組最初值，另列本次機率與修訂；三個期限有重疊，僅是描述性核對，不能稱為正式前瞻能力。重新整理、GET、全部更新及走勢匯出都不抓行情、不新增機率、不核對答案。正式08:30與歷史重建仍在原本兩個檢視。


## 收盤幅度與點數研究試算

原M1只有二分類機率，不提供報酬幅度。新增獨立`config/v6_night_points`研究模型：同四項已知夜盤／波動特徵，使用事前訓練的中位數分位回歸，再以校準期殘差10/50/90分位數形成期末收盤中位數與中央80%參考區間。點數=預估加權收盤−原加權收盤，不是台指期目標價，也不是上漲機率乘以指數或ATR。

固定訓練／校準／歷史測試日期與原包3一致，先固定設計再讀此次幅度模型的測試成績，不利用測試期重訓。該測試期已在先前其他研究打開，仍非全新盲樣本。三期限均勝過不變及歷史中位兩基準的預設研究顯示檢查；這不等於通過原正式採用規則或驗證夜盤盤中校準。名目80%區間的歷史測試涵蓋約77～79%。

對既有未到期情境，以`python -B -m backend.v6_night_points annotate-latest`另存補算時間與來源內容SHA，不能說它在原保存時間已發佈點數。首期限已到期則禁止補造。此舊版自動補算流程已停止：`v6_night_scenario publish`僅保存條件情境來源，不再自動保存點數或區間；原情境與原M1參數不改。GET及匯出只讀既有補算檔，不能重訓或新增。模型權重、協議及輸入SHA在獨立release保存。
