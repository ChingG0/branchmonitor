# 族群廣度（原型）

已整合至分點觀測站左側「族群流向」，券商關注也共用此處的族群字典。
`prototype/` 現為正式介面的依賴，請勿刪除。行情仍以 `mode=ro` 唯讀連線讀取
`data/monitor.sqlite3`；更新只寫原型資料庫與看板，不會啟動分點回補。
整合頁面不會自動更新；與獨立服務共用更新鎖，避免同時寫入。

## 檔案

```text
sector-seed.json   從「族群廣度看板」抽出的字典：670 族群、6,709 組成員關係、
                   39 家國際大廠、732 筆供應鏈連結，另含原看板快照供驗證
sectors.py         本機模組：匯入字典、重算指標、組出個股參考資料，供看板讀取
fetch_reference.py 抓台股產業鏈（47 鏈）、股本、月營收、三大法人買賣超、國際大廠報價
import_structure.py 匯入「產業營運結構」試算表：逐檔的上游／同業／下游對手方
build_board.py     把 sectors.report() 輸出成單檔 board.html
update.py          一次更新到本機可支援的最新交易日（法人、報價、指標、看板）
server.py          本機伺服器：啟動時自動更新，另提供手動更新 API
啟動族群看板.command  雙擊啟動；停止族群看板.command 雙擊停止
sectors.sqlite3    原型資料庫（字典 + 每日指標 + 產業鏈 + 股本營收），與正式庫分離
raw/               產業鏈與基本資料的原始回應快取，與正式的 data/raw/ 分開
board.html         看板，產生物
```

## 用法

```bash
cd prototype
python3 sectors.py seed              # 匯入字典（整批替換，不動已算好的指標）
python3 sectors.py compute           # 重算本機最新交易日
python3 sectors.py compute --date 2026-09-11
python3 fetch_reference.py all       # 抓產業鏈、股本、月營收、法人、報價
python3 fetch_reference.py institutional --days 20   # 只補法人買賣超
python3 fetch_reference.py quotes    # 只更新國際大廠報價
python3 import_structure.py          # 匯入產業營運結構試算表
python3 build_board.py               # 輸出 board.html
```

## 開啟與更新

雙擊 **啟動族群看板.command**，或：

```bash
python3 prototype/server.py
```

服務綁 `127.0.0.1:8787`，開 `http://127.0.0.1:8787/board.html`。
**啟動時會自動更新一次**，網頁可以先開著，完成後會自動重新載入。
頁面上方有「更新」按鈕可隨時手動更新，更新期間按鈕會停用並顯示進度。

每次更新做四件事：補三大法人買賣超（只補本機有行情的交易日）、重抓 39 家國際大廠
即時報價、計算目標日的族群指標（已算過就跳過）、重建 `board.html`。約 20 秒。

API：`GET /api/status` 讀狀態、`POST /api/refresh` 觸發更新（JSON `{}`，可傳 `{"force":true}`
重算已完成的項目）。只接受本機請求，寫入端檢查 Origin 與 Content-Type，與正式服務同一套做法。

### 行情來源與缺漏處理

正式系統的 `data/monitor.sqlite3` 一律**唯讀**（`mode=ro`），原型不寫入它。
但正式系統的自動更新目前是關閉的（`schedule_enabled=false`），行情可能停在較早的日期，
因此原型會**自己補抓缺少交易日的收盤價**，存進自己的 `own_prices`／`own_market_days`。

讀取時用 SQLite 的 ATTACH 加暫存檢視把兩邊合併：**正式系統有該日就一律以它為準**，
只有它沒有的日期才用原型自己那份。因此正式系統之後補上資料，原型這份會自動退居備援，
不會產生兩套互相打架的數字。行情解析直接借用 `backend.sources.parse_market()`，
與正式系統同一套驗證，但快取寫在 `prototype/raw/`，不碰 `data/raw/`。

**哪些訊號補不了**：分點榜單與成交重心只有正式系統會抓。原型自補行情的日期上，
這兩欄顯示「—」而不是 0，卡片下方也會標明該日尚未由分點觀測站同步。
法人買賣超與國際報價不受影響。

專案根目錄的 `.claude/launch.json` 也指向同一支 `server.py`（`prototype-board`，埠 8787），
與正式服務的 8765 無關。

`sectors.py build` 等於 seed + compute。指標只讀本機 `prices`，不連任何外部來源，
也不會觸發分點回補或 RS 重算。670 個族群整批重算約 1.5 秒。

## 主流族群

看板最上方，把三個訊號合到族群層級，左右分「資金流入／流出」，
可切換**當日資金**與 **5 日累計**兩種排序：

- **法人資金**＝當日**外陸資（不含外資自營商）＋投信**買賣超股數 × 收盤價，卡片同時列出兩者拆分。
- **成交重心**＝該族群有幾檔進入當日成交金額前 30 名（沿用正式系統已保存的成交重心）。
- **券商同步**＝該族群中有 2 家以上追蹤分點同日淨買超的檔數。
- 每張卡片列出金額最大的 5 檔貢獻股，點擊直接開個股明細；點卡片空白處會跳到族群排行並展開成員。
- 卡片同時顯示另一個期間的金額，並用標籤標出方向差異：**連續流入**（當日與 5 日皆正）、
  **單日反彈**（當日正但 5 日仍負）、**短線調節**（當日負但 5 日仍正）、**連續流出**（兩者皆負）。

5 日累計是**每日各自用當日收盤換算後相加**，不是用最後一天的價格回推整段。目前視窗為
2026-09-11～09-17。這個區分很關鍵：2026-09-17 當日晶圓代工法人淨流入 +203.9 億居冠，
但 5 日累計仍是 **−576.6 億**（單日反彈）；真正連續佈局的是金融族群——銀行 5 日 +152.3 億、
證券 +129.4 億、金控 +128.4 億，且主要由投信買進。

只納入**共動 ≥ 0.35、成員 3～30 檔**的族群。共動低的族群成員本來就不一起動，把它們的資金
加總當「族群資金流」會誤導。缺法人資料的個股不計為零，卡片另標缺漏檔數。

## 個股明細

點畫面上任何股票（族群成員、同環節同業、供應鏈台廠），或在搜尋框輸入後按 Enter。

- **當日資金流**：該股的外陸資與投信買賣超（億元與張數）、有幾家追蹤分點同步買超／賣超、
  當日成交金額排名、5 日法人累計與 5 日內的淨買天數。
- **營運結構**（來自你提供的試算表）：逐檔列出上游供應商、同業競爭者、下游客戶，依細分
  產業分組。對手方能對應到本機台股的顯示為可點擊個股，其餘（外商、未上市）顯示為灰底文字。
  涵蓋 502 檔主體，不是全市場。
- **台股產業鏈位置**：來自櫃買中心「產業價值鏈資訊平台」。對每條收錄該股的產業鏈，畫出
  上游／中游／下游的完整環節列，把該股所屬環節標亮，並列出同環節的其他上市櫃公司。
  47 條鏈中有 11 條原站就沒有分層（金融、軟體服務、交通運輸等），這些標為「未分層」。
- **股本**：公開資訊觀測站基本資料，含實收資本額與已發行普通股數。
  市值＝已發行股數 × 當日收盤，由本機行情計算。
- **營收**：月營收與累計營收（單位千元），另計累計年增率。

## 口徑

- **共動** = 成員日報酬的平均兩兩相關係數。逐對取雙方都有報酬的交易日（至少 20 個），
  只在成員數 3～30 檔時計算。2 檔算相關沒有統計意義；超過 30 檔的大分類本來就不會齊漲跌。
- **廣度** = 當日上漲成員數 ÷ 當日有報價成員數。分母用實際有報價的檔數，不是名單檔數。
- **報酬** 為未還原收盤價格報酬，不含股息與公司事件，與 branch-monitor 其他統計同口徑。
- **起算日報酬**以本機最早交易日（2026-01-02）為基準。本機沒有前一年最後交易日的收盤，
  因此介面標明起算日，不冒充 YTD。
- **佔比不是市占率**。畫面上的「市值佔比／營收佔比」是該股在**同一產業鏈環節、已上市櫃
  且有資料的成員**之中的合計佔比。它不等於真實產品市占率：同環節不含外商與未上市競爭者，
  公司營收通常橫跨多項業務，而一家公司也可能同時掛在多個環節。真實市占率（例如晶圓代工
  的全球市佔）需要付費研究機構資料，官方免費來源沒有。分母只加總有值的成員，缺值不當零。

## 驗證

以 2026-09-11 對照原看板快照（`sector-seed.json` 的 `snapshot`）：

| 指標 | 可比 | 相符 | 中位差 |
|---|---|---|---|
| 成員數 / 有報價數 | 670 | 670 (100%) | — |
| 共動 | 509 | 509 (100%) | 0.0002 |
| 今日報酬 r1 | 670 | 670 (100%) | 0.0025 |
| 廣度 | 670 | 670 (100%) | 0.0000 |
| 5 日報酬 r5 | 666 | 634 (95.2%) | 0.0027 |
| 20 日報酬 r20 | 635 | 596 (93.9%) | 0.0028 |

視窗長度（168 個交易日）與原看板完全一致。相符門檻為共動 0.02、報酬 0.01、廣度 0.005，
差距多半只是原看板四捨五入到小數 2 位。

驗證過程修掉兩個實際問題：

1. **共動高估**：最初只納入「整段視窗都有報價」的成員，停牌或有資料缺口的成員被整檔剔除，
   剩下 2～3 檔時相關係數被大幅高估（合金鋼 0.59 vs 實際 0.18）。改為逐對取共同交易日後完全吻合。
2. **廣度進度條沒有渲染**：`.bar .f` 是 inline span，`width`／`height` 百分比對 inline 元素無效，
   紅色填滿實際上寬高為零。加上 `display:block` 修正。（原看板有同樣問題。）

## 已知限制

- r5／r20 約 5～6% 的族群與原看板有差異，來自停牌股在區間內的處理方式。掃描過
  「整段完整」「最多缺 N 日」「缺漏 ≤X%」等規則，都不如現行的「兩端有價」貼近原值，
  因此保留兩端規則並在此載明，不逆向硬湊。期間停牌的個股，兩端相除會把缺口期間一併計入。
- 族群分類是多對多且父子並存（「系統整合」52 檔 ⊂「軟體業」89 檔），跨族群加總會重複計算。
- 71 個成員代碼在本機沒有報價（已下市或 `2250I`、`6598A` 等特殊代碼），列於成員但不計入廣度分母。
- 字典停在 2026-09-11 版，新上市、改分類、下市都不會自動更新。
- 法人買賣超只回補最近 20 個交易日（2026-08-21 起），不是整個觀察期間；5 日累計視窗
  取其中最近 5 個有資料的交易日。
- 營運結構試算表是靜態整理，沒有日期版本，也只涵蓋 502 檔主體；對手方有 2,735 個
  無法對應到本機台股（外商、未上市、港陸日股），顯示為灰底文字。
- 原看板「高廣度 20 日後 +8.2%、低廣度 −1.0%（t=3.40）」的預測力尚未在本機重驗；
  分月只有 3/5 個月成立，目前只當過濾條件，不當獨立訊號。

## 國際大廠報價與供應鏈

39 家國際大廠一張卡片，用 Yahoo Finance 取最新價與漲跌幅，依台股慣例**紅漲綠跌**，
依漲跌幅排序。**點卡片**開出該大廠的供應鏈明細：分「台廠供貨給大廠」與「大廠供貨給台廠」
兩個方向，各自依零件分類列出台廠，並帶當日漲跌幅；點任一台廠直接轉開個股明細。
原本獨立的「國際大廠供應鏈」區塊已移除，內容全部收進卡片裡。
MoneyDJ 代碼要轉成 Yahoo 代碼：`.US` 去後綴、`.KS` 保留、`.JP` 轉 `.T`、四碼數字加 `.HK`、
六碼陸股依 0/3 開頭給 `.SZ`、6 開頭給 `.SS`；德股的 `S@GR`／`X@GR` 沒有規則可推，逐檔對應。
報價可能延遲，時間戳直接顯示來源提供的時間。

**關於 `.tw` 後綴**：實測全表 3,829 個對手方中，只有 1 個寫成 `中聯資源9930.tw`，
其餘台股一律是 `東泥(1110)` 這種純括號格式（三個工作表分別有 282／908／342 個確認為台股）。

若之後來源能在每一檔台股都補上 `.tw`，這段驗證就可以簡化掉。

來源另有少量錯字會造成漏連（`敬鹏`／敬鵬、`申豊`／申豐、`豊藝`／豐藝、`凌E`／凌巨、

解析產業鏈頁時修掉三個問題：環節 `<div>` 的 class 後常接 `style`、部分環節名稱包在巢狀

## 尚未做
